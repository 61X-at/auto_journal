# Клиентские модули АвтоЖурнала

Данный каталог подготовлен по задаче **FE-003**. Пока приложение использует
статическую страницу `tempPage/index.html`, созданную в лабораторных № 4–5.
Ни один файл `src/` сейчас не подключён к HTML; это заготовки для следующих задач.

| Каталог / файл | Назначение | Задача backlog |
| --- | --- | --- |
| `main.js` | Точка входа клиентского приложения | FE-004 |
| `pages/` | Четыре раздела: главная, автомобиль, журнал, план ТО | FE-004 |
| `components/` | Общие кнопки, поля, карточки, пустое состояние, сообщения | FE-005 |
| `models/car.js` | Поля и проверка карточки автомобиля | FE-007 |
| `models/serviceEntry.js` | Поля и проверка события обслуживания | FE-009 |
| `models/maintenancePlan.js` | Поля и проверка плановой работы | FE-019 |
| `storage/localStorage.js` | Изолированный доступ к хранилищу браузера | FE-006 |
| `utils/expenses.js` | Вычисление расходов без зависимости от интерфейса | FE-016 |
| `utils/maintenanceDue.js` | Проверка сроков ТО по дате и пробегу | FE-021 |

## Правила разработки

1. `pages/` используют `components/`, модели, `storage/` и `utils/`, но не
   реализуют самостоятельно чтение/запись `localStorage`.
2. `models/` и `utils/` не знают о DOM и не обращаются к браузерному хранилищу.
3. `storage/` хранит чтение и запись под ключами
   `autojournal_v1_car`, `autojournal_v1_entries`, `autojournal_v1_plans`.
   Реализация будет добавлена только в **FE-006**.
4. Проект остаётся клиентским: нет backend, REST API, учётных записей и сетевых запросов.
5. Заготовки содержат только комментарии и `export {}`. Работающая логика
   добавляется строго в соответствующих задачах backlog.
