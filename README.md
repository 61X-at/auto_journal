# АвтоЖурнал — электронный журнал обслуживания автомобиля

**АвтоЖурнал** — учебный клиентский MVP для одного автомобиля. Доступны карточка автомобиля, история обслуживания, расходы и плановые работы ТО. Интерфейс адаптирован к телефону, планшету и компьютеру и работает без backend и регистрации.

## Возможности MVP

- **Автомобиль:** марка, модель, год и текущий пробег; изменение сведений; отображение на главной.
- **Журнал:** создание, редактирование и удаление записей с датой, типом, описанием, пробегом и стоимостью; поиск и фильтрация.
- **Расходы:** сумма и разбивка по категориям; фильтр по периоду включительно.
- **План ТО:** создание работы по дате и/или пробегу; отметка «Требует внимания» при достижении порога; завершение работ.
- **Главная:** актуальные автомобиль, ближайшее ТО и до трёх последних записей.
- **Надёжность:** сообщения об ошибках/успехе, проверки ввода, пустые состояния и управление с клавиатуры.

## Требования и локальный запуск

Нужны Node.js **20+** и npm. Выполняйте команды из корня репозитория:

```bash
npm ci
npm run dev
```

Откройте `http://localhost:5173/tempPage/index.html` (Vite обычно откроет страницу автоматически). Не открывайте HTML через `file://`: ES-модули работают через сервер.

## Тесты и статическая сборка

```bash
npm test               # все автоматические тесты
npm run test:storage   # надёжность localStorage
npm run test:expenses  # расчёты расходов
npm run test:study     # анализ пользовательских наблюдений
npm run test:release   # проверка конфигурации публикации
npm run build          # Vite + проверка dist
npm run preview        # локальный просмотр собранного сайта
```

**После успешной сборки** каталог `dist/` содержит `index.html` для GitHub Pages и приложение `tempPage/index.html` с JS/CSS в `assets/`. Корневая страница переводит пользователя в приложение, сохраняя hash-маршрут (`#/car`, `#/journal`, `#/maintenance`) и параметры URL. В Vite используется `base: './'`, чтобы статические ресурсы работали и в подпапке репозитория.

Команда `npm run build` завершится с ошибкой, если не удалось собрать приложение или отсутствуют необходимые файлы публикации. Наличие `dist/` само по себе ещё не подтверждает доступность опубликованного сайта.

## Публикация через GitHub Pages

После объединения FE-030 с `main`:

1. В GitHub откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Запустите workflow **Deploy AutoJournal to GitHub Pages** (вкладка Actions), либо выполните push в `main`.
3. Workflow установит зависимости, выполнит `npm test` и `npm run build`, загрузит `dist/` и опубликует его.
4. Скопируйте URL **после успешного запуска workflow**. Проверка реальной HTTPS-ссылки и пользовательского пути после публикации выполняется командой `npm run test:live` (FE-031).

Подробная инструкция и проверка: [`docs/deployment.md`](docs/deployment.md). **Не включайте `dist/` или `node_modules/` в коммит**, публикация автоматически собирается из исходников.

## Структура проекта

```text
.github/workflows/pages.yml  # CI-сборка и публикация GitHub Pages
public/index.html            # корневой переход для опубликованной версии
scripts/                     # проверка сборки, анализ пользовательского тестирования
src/components/              # переиспользуемые UI-компоненты
src/models/                  # проверка структуры данных
src/pages/                   # экраны приложения
src/storage/localStorage.js  # единый слой данных
src/utils/                   # фильтры, расходы, сроки ТО
src/main.js                  # hash-навигация
tempPage/index.html          # исходная HTML-страница Vite
tempPage/styles.css          # оформление и адаптивность
tests/                       # модульные, регрессионные и приёмочные тесты
docs/                        # документация
planning/                    # backlog / планирование
dist/                        # генерируется npm run build, не коммитится
```

## Демо-сценарий для защиты проекта

1. Откройте «Мой авто», сохраните **Toyota Camry, 2018 год, 125 000 км**. На главной должны появиться именно эти данные.
2. Перейдите в «Журнал» → «Добавить запись». Создайте запись «Замена масла» категории «ТО» с датой, пробегом и стоимостью **2 500 ₽**.
3. Создайте вторую запись «Замена фильтра» категории «замена детали» за **800 ₽**. Общая сумма расходов должна стать **3 300 ₽**.
4. Найдите «Замена фильтра» через поиск журнала, затем сбросьте поиск. Проверьте редактор и возврат в журнал.
5. На главной примените фильтр периода: выберите даты, включающие одну из записей. Убедитесь, что сумма изменилась; нажмите «Сбросить».
6. В разделе «План ТО» создайте работу «Следующая замена масла» с контрольным пробегом **125 000 км**. Работа должна получить статус «Требует внимания».
7. Вернитесь на главную: ближайшее ТО берётся из плана. В разделе плана нажмите «Выполнено» и убедитесь, что статус сохранился.
8. Обновите страницу браузера: данные автомобиля, журнала и планы ТО должны остаться на месте.

*Проводите демонстрацию в отдельном профиле браузера или на чистом сайте. Не очищайте существующие пользовательские данные ради демонстрации.*

## Ограничения и хранение данных

Данные сохраняются **только в `localStorage` конкретного браузера и адреса сайта**. Ключи: `autojournal_v1_car`, `autojournal_v1_entries`, `autojournal_v1_plans`. Данные не передаются на сервер. Нет аккаунтов, синхронизации, импорта/экспорта или резервного копирования. Очистка данных сайта, смена браузера или переход с localhost на GitHub Pages **не переносят данные** и могут привести к их потере. Не используйте приложение как единственное место хранения важных документов.

Текущий MVP рассчитан на **один автомобиль**. План ТО не создаёт запись в журнале автоматически при отметке выполнения. Проверка мобильной публикации и доступности URL выполняется отдельным workflow FE-031 на ширинах 1200 и 360 px.

## Опубликованная версия и финальная приёмка (FE-031)

**Демо:** https://61x-at.github.io/auto_journal/

После успешного деплоя запускайте живой smoke-тест HTTPS-сайта (в отличие от FE-028 он проверяет реальную публикацию и нативный `localStorage`):

```bash
python -m pip install "playwright>=1.50,<2"
python -m playwright install chromium
npm run test:live
```

Отдельный GitHub Actions workflow **Verify Published AutoJournal (FE-031)** автоматически запускается после успешного **Deploy AutoJournal to GitHub Pages** и проверяет опубликованный интерфейс в Chromium на 1200 и 360 px. Рабочий деплой не зависит от результата дополнительной проверки. Протокол, критерии приёмки и ручной чек-лист — в [`docs/fe031-final-acceptance.md`](docs/fe031-final-acceptance.md).

Сведения о локальной сборке и доступности Pages получены со слов владельца; итоговый статус функциональной проверки подтверждается только отчётом live-smoke, а не фактом успешного деплоя.
