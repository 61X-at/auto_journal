# Клиентские модули АвтоЖурнала

Данный каталог подготовлен по задаче **FE-003**. Пока приложение использует
статическую страницу `tempPage/index.html`, созданную в лабораторных № 4–5.
По FE-004 файл `src/main.js` подключён к `tempPage/index.html`: он переключает четыре страницы через hash-маршруты без перезагрузки.

| Каталог / файл | Назначение | Задача backlog |
| --- | --- | --- |
| `main.js` | Маршрутизация, обновление активной навигации и заголовка | FE-004 |
| `pages/` | Четыре раздела: главная, автомобиль, журнал, план ТО; статические макеты | FE-004 |
| `components/` | Общие кнопки, поля, карточки, пустое состояние, сообщения | FE-005 |

## Правила разработки

1. `pages/` используют `components/`, модели, `storage/` и `utils/`, но не
   реализуют самостоятельно чтение/запись `localStorage`.
2. `models/` и `utils/` не знают о DOM и не обращаются к браузерному хранилищу.
3. `storage/` хранит чтение и запись под ключами
   `autojournal_v1_car`, `autojournal_v1_entries`, `autojournal_v1_plans`.
   Реализовано в **FE-006**: безопасное чтение, запись и обработка ошибок.
4. Проект остаётся клиентским: нет backend, REST API, учётных записей и сетевых запросов.
5. Реализованы переходы между разделами (FE-004) и общие DOM-компоненты
   (`components/`, FE-005). Модели, хранение и расчёты пока остаются заготовками.
6. URL разделов: `#/home`, `#/car`, `#/journal`, `#/maintenance`. Ссылка
   открывает раздел без полной перезагрузки, работают Назад/Вперёд.

## FE-005: общие компоненты

- `Button.js`: единый элемент `<button>` для действий и `<a>` для переходов.
- `FormField.js`: поле + `label`, `required`, ошибка с `aria-describedby`, валидация.
- `SummaryCard.js`: карточка сводки, используется трижды на главной.
- `EmptyState.js`: состояние списка без записей, пример на странице журнала.
- `ErrorNotice.js`: общая ошибка формы (`role="alert"`).
- `DemoForm.js`: две тестовые формы в разделах «Автомобиль» и «Журнал».
  Форма только проверяет заполнение; изменение данных — **не FE-005**.

## FE-006: локальный слой данных

`storage/localStorage.js` предоставляет функции `readCar`, `readEntries`,
`readPlans`, `saveCar`, `saveEntries`, `savePlans` (и общие
`readLocalData`/`writeLocalData`). Они возвращают результат `{ ok, status, data? , message? }`,
а не выбрасывают исключения при ошибках доступа к браузерному хранилищу.

Ключи: `autojournal_v1_car`, `autojournal_v1_entries`, `autojournal_v1_plans`.
Пустое хранилище возвращает `null` для автомобиля и `[]` для списков.
Повреждённый JSON или сбой доступа возвращает безопасное состояние и сообщение,
не очищая сохранённые данные. Корневые типы данных проверяются; детальная
валидация полей относится к FE-007/009/019. В страницах пока демо-данные,
но при повреждённом хранилище отображается уведомление и безопасное состояние.
Формы начнут сохранять реальные данные в следующих задачах.

Тесты: `npm test`.

## FE-007: модель автомобиля

`models/car.js`: `validateCar(input)` нормализует четыре поля автомобиля
(`brand`, `model`, `year`, `currentMileage`) и возвращает ошибки по полям.
Проверка не обращается к браузеру и не сохраняет данные. При `ok: true`
результат `data` можно передавать в `storage.saveCar()` из FE-006.
Сборка интерфейса редактирования и вызов этих функций из формы — FE-008.


### FE-008 — форма карточки автомобиля

`pages/CarPage.js` реализует создание и изменение одного автомобиля на странице `#/car`.
Поля создаются переиспользуемым `components/FormField.js`; ошибки привязаны к полям.
`saveCarFormData()` проверяет значения функцией `models/car.js::validateCar` и
сохраняет корректные данные через `storage/localStorage.js::saveCar`.
Повреждённое хранилище не перезаписывается автоматически.
Тесты: `tests/fe008-car-form.test.mjs`.
Другие разделы приложения в FE-008 не меняются.
