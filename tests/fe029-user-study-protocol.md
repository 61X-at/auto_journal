# FE-029 — протокол короткого пользовательского тестирования

**Основание:** backlog FE-029, неделя 8. **Цель:** наблюдать, как 2–3 реальных владельца автомобиля без подсказок добавляют запись о ТО и находят прежнюю замену детали. Ориентиры: 60 с и 20 с соответственно. Критерий: отдельно отметить, достигнуты ли ориентиры минимум у двух из трёх участников.

**Статус:** подготовлен сценарий; наблюдения участников пока **не проводились и не утверждаются**. Автотесты FE-028 не считаются пользовательским исследованием.

## 1. Условия проведения

- Пригласить 2–3 добровольцев, имеющих автомобиль. Оценка «2 из 3» возможна только после наблюдения всех трёх; с двумя участниками можно составить предварительный отчёт.
- Каждый работает самостоятельно на одинаковом устройстве и с одинаковыми заранее подготовленными тестовыми данными. Если цель — сравнить мобильный и настольный интерфейсы, фиксировать устройство в `notes` и не смешивать группы при интерпретации.
- **Использовать отдельный временный профиль браузера**, не рабочий профиль разработчика: загрузка фикстуры заменит автомобиль, журнал и план ТО в `localStorage` текущего профиля.
- Убедиться, что `npm run dev` запущен и открывается `/tempPage/index.html`. Перед каждым участником сбросить временный профиль и подготовить данные по `tests/fe029-test-data.md`.
- Не собирать реальные номера автомобилей, ФИО, телефоны или личные сведения. Обозначить людей только `P01`, `P02`, `P03`. Попросить устное согласие на фиксацию времени и безличных замечаний. Фото/видео не обязательны, для них нужно отдельное согласие.
- Модератор фиксирует ошибки и реальные высказывания без их приписывания другим участникам. **Во время задания не подсказывать**, какие ссылки и кнопки нажимать. Если пришлось помочь, `completed=no` (выполнено не самостоятельно), описать помощь в `problems`.

## 2. Единые задания

Подготовить фикстуру (автомобиль Kia Rio 2019 года, пробег 87 400 км и пять старых событий). До каждого задания модератор открывает **главную страницу**. Подготовка и переход на главную не входят во время задания.

### Задание А. Добавление записи (ориентир ≤ 60 с)

Прочитать участнику только:

> «Внесите в приложение выполненную работу: тип — ТО, описание — „Замена моторного масла“, дата — 20.10.2026, пробег — 87 400 км, стоимость — 3 200 ₽. Когда запись будет сохранена, скажите „готово“.»

**Старт секундомера:** сразу после предъявления задания и сигнала участника «начинаю». **Финиш:** когда запись действительно сохранена и видна в журнале. Для успеха все поля должны совпадать с заданием, пользователь должен справиться без подсказок. Ошибочная/несохранённая запись = `completed=no`, даже если пользователь сказал «готово».

### Задание Б. Поиск прежней замены (ориентир ≤ 20 с)

Вернуть приложение на главную *до* начала измерения; ничего не объяснять про поиск. Прочитать:

> «Найдите в истории прежнюю замену воздушного фильтра и скажите, **когда** она была и **сколько стоила**.»

**Правильный ответ:** 15.03.2026, 900 ₽. **Старт:** после прочтения задания и сигнала «начинаю». **Финиш:** после правильного ответа с опорой на экран приложения. Любой самостоятельный способ поиска (по строке, через журнал и т. д.) допустим.

**Если участник не справляется:** дайте закончить попытку, но можно остановить её после 180 с для задания А или 120 с для Б и записать фактически затраченное время. Не выдавайте это время за успешное выполнение. Если подсказка всё же дана, фиксируйте её и считайте самостоятельное выполнение неуспешным.

## 3. Таблица результатов

Заполнять `tests/fe029-session-results.csv`, в нём уже предусмотрены **3 участника × 2 задания**:

| Поле | Как заполнять |
|---|---|
| `participant_id` | `P01`, `P02` или `P03`, без личных данных |
| `task_id` | `add` или `find`; **не переименовывать** |
| `completed` | `yes` — без подсказок и с верным результатом; `no` — иначе; пусто — ещё не проводилось |
| `time_seconds` | Реальное измеренное целое число секунд, даже при `no`; не ставить 0 |
| `problems` | Наблюдённые затруднения или слово `нет` |
| `notes` | Краткие дословные замечания, тип устройства, контекст; можно оставить пустым |

CSV допускает кавычки и запятые внутри замечаний. Не вставляйте в него персональные данные. После заполнения выполняйте:

```bash
npm run study:report
```

Команда проверит полноту и корректность данных, создаст `tests/fe029-results.md` с таблицей времени/затруднений и сравнением с порогами. Пока всех трёх участников не наблюдали, итог «2 из 3» помечается **«недостаточно данных»**, а не «не достигнут».

## 4. Интерпретация и завершение FE-029

Для каждого задания отдельно:

1. Порог выполнен конкретным участником только если `completed=yes` **и** `time_seconds ≤ 60` (`add`) / `≤ 20` (`find`).
2. После участия трёх человек посчитать, достигнут ли результат **минимум у двух из трёх**. Если задача выполнена самостоятельно, но медленнее порога, цель скорости **не** достигнута.
3. В `tests/fe029-observations.md` по реальным заметкам выделить повторяющиеся проблемы и улучшения; генератор этот файл не перезаписывает. Без реальных наблюдений нельзя писать «пользователи довольны» или «цели достигнуты».
4. Сохранить обезличенный отчёт, протокол и таблицу результатов в ветку FE-029, создать Pull Request. Изменения продукта по новым замечаниям — отдельные исправления с собственными задачами, а не предположение о результатах этой проверки.

Отдельно обсудить с участником после заданий: «Где было трудно? Что вы ожидали увидеть? Что стоило бы изменить?» Ответы занести в `notes` либо `tests/fe029-observations.md`, отделяя слова участника от наблюдений модератора.
