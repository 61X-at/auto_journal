# АвтоЖурнал (AutoJournal)

Учебный клиентский веб-проект для ведения истории обслуживания одного автомобиля.

## Текущий этап: FE-009 — модель событий обслуживания

На странице «Автомобиль» можно добавить один автомобиль, изменить марку, модель,
год выпуска и пробег. Данные проверяются модулем FE-007 и сохраняются через
`src/storage/localStorage.js` (FE-006) по ключу `autojournal_v1_car`.
После перезагрузки карточка и заполненные поля восстанавливаются. При ошибках
показываются пояснения рядом с полями; при ошибке хранилища приложение не
выдаёт ложное подтверждение об успешном сохранении.

Вкладки «Главная», «Журнал» и «План ТО» **пока демонстрационные**.
FE-009 добавляет в `src/models/serviceEntry.js` модель событий и валидацию,
не создавая форму добавления записей (это FE-010).
Интеграция журнала, фильтров и расчётов относится к следующим задачам backlog.
Backend и авторизация не входят в MVP.

## Запуск

**Важно для FE-004:** файл `tempPage/index.html` нельзя открывать двойным щелчком (`file://`). Навигация использует ES-модули; при прямом открытии браузер может заблокировать их загрузку.

**Через Vite:**

```bash
npm install
npm run dev
```

При запуске через Vite откройте **`http://localhost:5173/tempPage/index.html`** (команда `npm run dev` автоматически откроет этот адрес, если браузер настроен). Запускайте команды именно из корня репозитория, не из папки `tempPage`.

Проверка сборки:

```bash
npm run build
```

## Что проверять для ЛР № 5

1. CSS подключён в `<head>` через `<link rel="stylesheet" href="./styles.css">`.
2. Элементы оформлены с помощью понятных классов.
3. Сетка панелей построена на CSS Grid, внутреннее выравнивание — на Flexbox.
4. На широком экране навигация находится слева, на планшете — сверху, на телефоне — снизу.
5. На узких экранах формы и карточки перестраиваются в один столбец, нет горизонтального переполнения страницы.
6. Использованы семантические `header`, `nav`, `main`, `section`, `article`, `aside`, `footer` и подписи к полям.

## Каркас и навигация (FE-004)

В рамках FE-004 реализованы четыре статических раздела: «Главная»,
«Автомобиль», «Журнал» и «План ТО». В `tempPage/index.html` подключён

## Переиспользуемые компоненты (FE-005)

В `src/components/` реализованы `Button`, `FormField`, `SummaryCard`,
`EmptyState`, `ErrorNotice` и вспомогательная демонстрационная форма `DemoForm`.
Компонент `FormField` используется **в двух разных формах**: на страницах
«Автомобиль» и «Журнал» (раскрыть блок «Проверить общие компоненты формы»).

Для проверки критерия приёмки FE-005 откройте обе формы и нажмите
«Проверить поля» с пустыми полями: ошибочные поля получают `aria-invalid` и
связь с конкретным текстом ошибки через `aria-describedby`. Заполните поля
и проверьте сообщение об успешной проверке. Оно **не означает сохранение** —
редактирование автомобиля и добавление записей относятся к следующим задачам.

На главной три карточки сводки формируются одним компонентом `SummaryCard`.
В журнале раскрывается демонстрационный пример `EmptyState`; `ErrorNotice`
используется обеими формами. Данные во всех разделах пока тестовые.

Проверка запуска: `npm install`, `npm run dev`, затем
`http://localhost:5173/tempPage/index.html`.

## Локальный слой данных (FE-006)

Создан `src/storage/localStorage.js` для чтения и записи автомобиля, записей
и плана ТО под ключами версии 1. При пустом хранилище возвращается безопасное
значение (`null` / `[]`). Если JSON повреждён или браузер блокирует запись,
модуль возвращает сообщение об ошибке, а приложение показывает предупреждение.
Данные автоматически не удаляются; сетевые запросы не используются.

**Граница задачи:** формы и демонстрационные карточки пока не используют
сохранённые значения. Подключение бизнес-сценариев выполняется далее по backlog.

Проверки: `npm test`, `npm run dev`, `npm run build`.

## Модель автомобиля и проверки (FE-007)

`src/models/car.js` экспортирует `CAR_FIELDS`, `MIN_CAR_YEAR` и
`validateCar(input)`. Результат проверки: `{ ok: true, data, errors: {} }`
или `{ ok: false, data: null, errors }`, где `errors` содержит сообщения
по конкретным полям. Марка и модель обязательны, строки обрезаются;
год выпуска — целое число от 1886 до следующего календарного года;
пробег — целое неотрицательное число. Числа могут приходить строками из формы.

Модель не сохраняет данные самостоятельно. Для проверки сохранения тесты
используют `saveCar` и `readCar` из FE-006. Подключение формы и вывод ошибок
на странице автомобиля запланированы на FE-008.

```bash
npm test
```

## Проверка FE-008 (форма автомобиля)

1. Запустите `npm install`, `npm test`, `npm run dev`.
2. Откройте `http://localhost:5173/tempPage/index.html#/car`.
3. Сначала нажмите «Сохранить автомобиль» без заполнения — поля должны показать ошибки.
4. Введите, например: Toyota / Camry / 2020 / 85000 и сохраните.
5. Убедитесь, что карточка появилась. Обновите страницу — значения должны остаться.
6. Измените пробег на 90000, сохраните и обновите страницу повторно.
7. Попробуйте отрицательный пробег: форма должна показать ошибку, а сохранённое значение 90000 не должно измениться.
8. В DevTools → Application → Local Storage проверьте ключ `autojournal_v1_car`.

Важно: на главной странице пока остаётся демонстрационная Lada Vesta.


## FE-009 — модель события обслуживания

`src/models/serviceEntry.js` экспортирует `SERVICE_ENTRY_TYPES`,
`SERVICE_ENTRY_FIELDS`, `validateServiceEntry(input)` и `createServiceEntry(input)`.
Модель описывает `id`, `type`, `date`, `mileage`, `description`, `amount`.
Разрешённые типы: `ТО`, `ремонт`, `замена детали`, `покупка`.
Дата задаётся как `YYYY-MM-DD` и проверяется по календарю, пробег —
неотрицательное целое число, стоимость — неотрицательное число, описание
обязательно. Строковые значения из формы нормализуются.

`validateServiceEntry()` возвращает `{ ok, data, errors }` без изменений хранилища.
`createServiceEntry()` только при успешной проверке создаёт новый уникальный
`id` (не доверяет `id`, пришедшему от формы). Для проверки совместимости с
`FE-006` тесты сохраняют массив через `saveEntries` и читают через
`readEntries`. Форма и реальное добавление записи — задача FE-010.

Тесты: `npm test` (16 новых проверок в `tests/fe009-service-entry.test.mjs`).
