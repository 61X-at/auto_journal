# АвтоЖурнал (AutoJournal)

Учебный клиентский веб-проект для ведения истории обслуживания одного автомобиля.

## Текущий этап: FE-017 — реальная сводка расходов и фильтр периода

На странице «Автомобиль» можно добавить один автомобиль, изменить марку, модель,
год выпуска и пробег. Данные проверяются модулем FE-007 и сохраняются через
`src/storage/localStorage.js` (FE-006) по ключу `autojournal_v1_car`.
После перезагрузки карточка и заполненные поля восстанавливаются. При ошибках
показываются пояснения рядом с полями; при ошибке хранилища приложение не
выдаёт ложное подтверждение об успешном сохранении.

На главной последние записи загружаются из localStorage (FE-014), а сводка расходов и разбивка по категориям рассчитываются из тех же записей (FE-016—017). Карточка автомобиля и «План ТО» пока остаются демонстрационными.
Вкладка «Журнал» показывает сохранённые записи **от новых событий к старым**,
позволяет добавить запись, отредактировать её через форму с сохранением ID
или удалить после подтверждения. После удаления список сразу обновляется. При пустом
журнале есть кнопка создания первой записи. Поиск и фильтры доступны с FE-013. Расходы рассчитываются функциями FE-016 и показываются на главной (FE-017) с выбором периода по датам и сбросом фильтра.
Backend и авторизация не входят в MVP.

## Запуск

**Важно для FE-004:** файл `tempPage/index.html` нельзя открывать двойным щелчком (`file://`). Навигация использует ES-модули; при прямом открытии браузер может заблокировать их загрузку.

Проверка сборки:

```bash

```

## Переиспользуемые компоненты (FE-005)

В `src/components/` реализованы `Button`, `FormField`, `SummaryCard`,
`EmptyState`, `ErrorNotice` и вспомогательная демонстрационная форма `DemoForm`.
Компонент `FormField` используется **в двух разных формах**: на страницах

На главной три карточки сводки формируются одним компонентом `SummaryCard`.
В журнале раскрывается демонстрационный пример `EmptyState`; `ErrorNotice`
используется обеими формами. Данные во всех разделах пока тестовые.

Проверка запуска: `npm install`, `npm run dev`, затем
`http://localhost:5173/tempPage/index.html`.

## Локальный слой данных (FE-006)

Создан `src/storage/localStorage.js` для чтения и записи автомобиля, записей
и плана ТО под ключами версии 1. При пустом хранилище возвращается безопасное
значение (`null` / `[]`). Если JSON повреждён или браузер блокирует запись,
модуль возвращает сообщение об ошибке, а приложение показывает предупреждение.
Данные автоматически не удаляются; сетевые запросы не используются.

**Граница задачи:** формы и демонстрационные карточки пока не используют
сохранённые значения. Подключение бизнес-сценариев выполняется далее по backlog.

Проверки: `npm test`, `npm run dev`, `npm run build`.

## Модель автомобиля и проверки (FE-007)

`src/models/car.js` экспортирует `CAR_FIELDS`, `MIN_CAR_YEAR` и
`validateCar(input)`. Результат проверки: `{ ok: true, data, errors: {} }`
или `{ ok: false, data: null, errors }`, где `errors` содержит сообщения
по конкретным полям. Марка и модель обязательны, строки обрезаются;
год выпуска — целое число от 1886 до следующего календарного года;
пробег — целое неотрицательное число. Числа могут приходить строками из формы.

Модель не сохраняет данные самостоятельно. Для проверки сохранения тесты
используют `saveCar` и `readCar` из FE-006. Подключение формы и вывод ошибок
на странице автомобиля запланированы на FE-008.

```bash
npm test
```

## Проверка FE-008 (форма автомобиля)

1. Запустите `npm install`, `npm test`, `npm run dev`.
2. Откройте `http://localhost:5173/tempPage/index.html#/car`.
3. Сначала нажмите «Сохранить автомобиль» без заполнения — поля должны показать ошибки.
4. Введите, например: Toyota / Camry / 2020 / 85000 и сохраните.
5. Убедитесь, что карточка появилась. Обновите страницу — значения должны остаться.
6. Измените пробег на 90000, сохраните и обновите страницу повторно.
7. Попробуйте отрицательный пробег: форма должна показать ошибку, а сохранённое значение 90000 не должно измениться.
8. В DevTools → Application → Local Storage проверьте ключ `autojournal_v1_car`.

Важно: на главной странице пока остаётся демонстрационная Lada Vesta.


## FE-009 — модель события обслуживания

`src/models/serviceEntry.js` экспортирует `SERVICE_ENTRY_TYPES`,
`SERVICE_ENTRY_FIELDS`, `validateServiceEntry(input)` и `createServiceEntry(input)`.
Модель описывает `id`, `type`, `date`, `mileage`, `description`, `amount`.
Разрешённые типы: `ТО`, `ремонт`, `замена детали`, `покупка`.
Дата задаётся как `YYYY-MM-DD` и проверяется по календарю, пробег —
неотрицательное целое число, стоимость — неотрицательное число, описание
обязательно. Строковые значения из формы нормализуются.

`validateServiceEntry()` возвращает `{ ok, data, errors }` без изменений хранилища.
`createServiceEntry()` только при успешной проверке создаёт новый уникальный
`id` (не доверяет `id`, пришедшему от формы). Для проверки совместимости с
`FE-006` тесты сохраняют массив через `saveEntries` и читают через
`readEntries`. Форма и реальное добавление записи — задача FE-010.

Тесты: `npm test` (16 новых проверок в `tests/fe009-service-entry.test.mjs`).


### FE-010 — Создание записи обслуживания

Откройте `#/journal/new` через кнопку «Добавить запись» на главной или в журнале.
Введите тип, дату, целочисленный пробег, описание и стоимость. При успешном
сохранении запись добавляется к массиву `autojournal_v1_entries` и отображается
на странице `#/journal` после перехода/перезагрузки. Данные хранятся только
в текущем браузере. Повреждённое хранилище не перезаписывается.

В FE-011 журнал показывает записи по дате. Поиск, редактирование и удаление
относятся к следующим задачам.
Главная страница всё ещё демонстрирует статические карточки и статистику.

Проверки: `npm test`, `npm run build`, `npm run dev`.


### FE-011 — История обслуживания по дате

`src/utils/serviceHistory.js` сортирует копию массива `ServiceEntry` по `date`
(новые выше старых). Совпадающие даты сохраняют исходный порядок.
`JournalPage.js` выводит дату, категорию, описание, пробег и стоимость.
Если записей нет, показывается пустое состояние с кнопкой **«Добавить запись»**,
открывающей `#/journal/new`.

Проверка: сохраните сначала запись от 01.01.2026, а затем от 15.10.2026.
На странице `#/journal` октябрьская запись должна стоять первой. Обновление
страницы сохраняет такой порядок. Для пустого состояния используйте отдельное
тестовое окно браузера с чистым localStorage — удалять реальные записи не нужно.

`npm test` запускает тесты сортировки, полей карточек и безопасности вывода.
Задачи FE-012 (редактирование), FE-013 (поиск) и FE-014 (последние записи на главной)
в этой ветке не реализуются.

## FE-012: редактирование и удаление

- Маршрут `#/journal/edit/<id>` открывает заполненную форму выбранного события.
- `src/utils/serviceEntryActions.js` содержит операции `updateServiceEntry` и
  `deleteServiceEntry` с проверками и безопасной записью через FE-006.
- У обновлённой записи сохраняется прежний ID; другие записи не изменяются.
- Удаление требует подтверждения браузерным диалогом и обновляет список без перезагрузки.
- Тесты: `tests/fe012-edit-delete.test.mjs`; запуск: `npm test`.

### FE-013 — Поиск и фильтрация

- Поиск выполняется по `description` без учёта регистра; фильтр работает по сохранённому `type`.
- Поиск и категория комбинируются, результаты остаются отсортированы по дате.
- На главной поиск открывает журнал с параметрами в адресе `#/journal?q=...&type=...`.
- Пустой журнал и запрос без совпадений имеют разные состояния; кнопка «Сбросить фильтры» показывает полный список.
- Это только чтение данных, изменение и удаление записей остаются функцией FE-012. Последние реальные записи на главной появятся в FE-014.


### FE-014 — Последние события на главной

- Главная выводит не больше трёх самых новых событий по дате из `autojournal_v1_entries`.
- Каждая краткая запись показывает описание, дату, тип и стоимость. Под ней нет кнопок изменения и удаления — эти действия доступны в журнале.
- Ссылка «Все записи» ведёт в `#/journal`; поиск на главной по-прежнему открывает журнал с выбранными условиями (FE-013).
- При отсутствии событий появляется сообщение «Пока нет записей» и ссылка на форму добавления. При ошибке чтения демонстрационные события не подставляются.
- По требованиям backlog расчёт суммарных расходов и ближайшего ТО остаются отдельными задачами FE-017 и FE-023.
- Проверка: `npm test`; вручную добавить четыре события и убедиться, что на главной показаны только три самых новых.

## FE-015 — мобильная история обслуживания

Журнал (`#/journal`) использует тот же DOM со всеми полями и кнопками на компьютере и телефоне. При ширине экрана до 620 px записи перестраиваются в вертикальные карточки: описание и дата/тип/пробег сверху, цена справа, действия в две удобные для нажатия колонки. Список не требует горизонтальной прокрутки даже на 360 px. Данные и функции FE-011—FE-014 не изменены.

## FE-016 — Расчёт расходов (без изменений интерфейса)

Реализованы чистые функции `calculateTotalExpenses`,
`calculateExpensesByCategory`, `calculateExpenseSummary` в `src/utils/expenses.js`.
Вход — сохранённые события `ServiceEntry` (FE-009) и необязательный период
`{ startDate, endDate }` включительно. Расходы вычисляются заново по событиям,
отдельно в `localStorage` не сохраняются. Неверные даты и записи приводят к
ошибке вместо некорректного отчёта. В FE-016 главная страница не меняется:
отображение реальной сводки расходов и фильтра периода относится к FE-017.

Проверки: `npm test` и `npm run build`.

## FE-017 — Сводка расходов и выбор периода

На главной странице раздел «Коротко о главном» читает события из
`autojournal_v1_entries` при каждом открытии главной страницы и показывает:

- общую сумму расходов из FE-016 в ₽, рассчитанную по сохранённым событиям;
- число сохранённых записей и прежнюю демонстрационную карточку ближайшего ТО;
- детализацию затрат по четырём категориям: ТО, ремонт, замена детали, покупка;
- форму «С даты» / «По дату» с кнопками «Показать» и «Сбросить».

Обе границы интервала включаются. Пустая дата означает отсутствие ограничения.
Если границы перепутаны, выводится ошибка рядом с полем, прежняя сумма остаётся.
Если записи не подходят по датам, отображаются 0 ₽ и пояснение. При ошибке
чтения `localStorage` приложение не изображает потерянные данные нулевыми расходами.
Суммы не записываются отдельно: при следующем открытии главной автоматически
пересчитываются из текущих данных журнала.

Проверка: `npm test` (151 тест), `npm run build`, `npm run dev` и
ручной сценарий из инструкции FE-017.

## FE-018 — Регрессионные тесты расчёта расходов

Ветка FE-018 добавляет фиксированный набор из 12 тестовых событий
(`tests/fixtures-expense-data.mjs`) и тесты
`tests/fe018-expense-regression.test.mjs`. Ожидаемые суммы записаны явно,
а не вычисляются тестами из проверяемого модуля.

- `npm run test:expenses` — **только** проверки FE-018, без браузера и Vite.
- `npm test` — все тесты проекта, включая FE-018.

Проверяются общая сумма, суммы по четырём категориям, пустые данные,
пустой период, включение границ дат, високосная дата, нулевая стоимость,
перенос записи в другую категорию и неизменность исходных данных.
Расчётные функции FE-016 и интерфейс FE-017 в этой ветке не меняются.
