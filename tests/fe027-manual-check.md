# FE-027 — Ручная приёмка localStorage

Версия: после FE-026. Выполняется на **отдельном тестовом профиле браузера**.

> **Осторожно:** пункты с очисткой/повреждением данных уничтожают или делают
> недоступными хранимые значения. **Не проводите их на единственной копии
> настоящего журнала.** Для проверки используйте отдельный профиль браузера.

## Подготовка

1. `npm ci && npm test && npm run dev`; открыть `http://localhost:5173/tempPage/index.html`.
2. Открыть DevTools → Application → Local Storage, найти origin открытой страницы.
3. Все три ключа: `autojournal_v1_car`, `autojournal_v1_entries`, `autojournal_v1_plans`.
4. На тестовом профиле вначале нет этих ключей. Очистку осуществлять **только там**.

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть чистый профиль, пройти главную / «Мой авто» / журнал / «План ТО» | Нет белого экрана; показаны понятные пустые состояния; записи не придуманы |
| 2 | Создать автомобиль Toyota Camry, пробег 125000 | Автомобиль виден на странице «Мой авто» и главной |

| 4 | Создать план ТО «Замена фильтра», 130000 км | Работа появилась в активных планах, видна на главной как ближайшее ТО |
| 5 | Перезагрузить страницу и последовательно открыть все разделы | Все три вида данных остались, суммы не сбросились |
| 6 | Отметить работу как выполненную и снова обновить страницу | Статус `done` сохранился, работа во «Выполненные», исходный журнал не изменён |
| 7 | **Только на тестовом профиле:** вручную заменить значение `autojournal_v1_entries` на `{broken` и обновить | Вместо списка — предупреждение об ошибке и безопасное состояние; остальные разделы работают; `{broken` не удаляется автоматически |
| 8 | Аналогично проверить `autojournal_v1_car` и `autojournal_v1_plans` по одному ключу (восстанавливая значения между проверками) | Предупреждение и безопасное состояние, без потери соседних данных и белого экрана |
| 9 | Запретить доступ к storage в настройках браузера или использовать тестовую среду, где `getItem` бросает `SecurityError` | Маршруты доступны, показано предупреждение, кнопки опасного сохранения недоступны |
| 10 | Смоделировать `QuotaExceededError` при `setItem`; попробовать сохранение нового события / авто / плана | Виден текст ошибки, успех не сообщается, введённые значения остаются в форме; предыдущие данные не перезаписаны |

## Ограничения и риски

- `localStorage` привязан к **origin** (схема, домен, порт). Другой порт или браузер имеет отдельное хранилище.
- Очистка данных сайта, удаление профиля браузера, приватный режим и некоторые настройки конфиденциальности могут уничтожить данные. В MVP **нет резервных копий, сервера или восстановления после очистки**.
- Ошибка доступа **не равна** пустому журналу: приложение сообщает о проблеме и не должно автоматически перезаписывать неизвестные значения.
- Не следует вручную удалять повреждённые ключи, пока не сделана копия: сохранившееся содержимое ещё может потребоваться для восстановления вручную.
- Сообщение об успешном сохранении ожидается **только после успешного `setItem`**.
